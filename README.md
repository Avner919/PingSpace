# PingSpace

Русскоязычный прототип бронирования одного или нескольких столов для настольного тенниса. Одна локация: Москва, Тверская, 11; три стола, работа 24/7. React, Vite, Tailwind CSS 4, shadcn/ui и Node.js с Neon Postgres.

## Запуск

Node.js **24.x** (также проверено на 26.13.1) и npm:

```cmd
cd /d C:\Projects\GitHub\PingSpace
npm install
npm run dev -- --port 5173 --strictPort
```

Откройте http://127.0.0.1:5173/ . API запускается вместе с Vite и подключается к Neon: дополнительный процесс базы не нужен. Для работы необходим интернет. Сервер должен оставаться запущенным.

Для собранной версии:

```cmd
npm run build
npm start
```

По умолчанию сервер слушает 127.0.0.1:5173. `HOST` и `PORT` меняют адрес и порт; `PINGSPACE_PUBLIC_ORIGIN` задаёт точный внешний origin при размещении за HTTPS-прокси и включает Secure у cookie.

## Аккаунты и вход из другого браузера

1. Нажмите «Войти» → «Регистрация», укажите e-mail и пароль от 10 до 128 символов.
2. В другом браузере откройте **тот же сервер PingSpace**, нажмите «Войти» и используйте тот же e-mail и пароль.
3. Аккаунт, ваши брони и доступность столов общие для всех браузеров. Каждый браузер получает независимую сессию; выход в одном не завершает остальные.
4. Аккаунт сохраняется после перезапуска сервера. Сессии действуют до 30 дней, пока пользователь не выйдет или администратор не сменит его учётные данные.

Пароли хранятся как scrypt-хеши с отдельными случайными salt; браузер получает случайную сессию в HttpOnly/SameSite-cookie, а сервер хранит её хеш. Регистрация всегда создаёт роль игрока; роль администратора не назначается из браузера.

Прежний вход без пароля был браузерной имитацией. Для такого e-mail нужно один раз зарегистрировать серверный аккаунт с паролем. Старые localStorage-записи не удаляются, но автоматически не импортируются в новую базу: их владельцы и роли раньше не проверялись. Письма, подтверждение адреса и восстановление забытого пароля пока не настроены.

## Постоянное хранение

Локальные `npm run dev`, `npm run preview`, `npm start` и `npm run admin` используют Neon Postgres. При текущих настройках база общая с опубликованным сайтом: аккаунты и брони, созданные локально, видны и на сайте после входа. Изменения и отмены также общие.

Подключение выбирается по приоритету: переменная окружения `DATABASE_URL`, затем `DATABASE_URL` из `.env.local`, затем из `.env.vercel.local`. В этом проекте уже есть локальный файл подключения. Для получения настроек на другом компьютере:

```cmd
vercel env pull .env.vercel.local --environment=production
```

Либо запишите `DATABASE_URL=...` из Neon в `.env.local`. Эти файлы не включаются в Git. Не используйте префикс `VITE_` для секретов базы. Другие переменные из файлов Vercel не загружаются в локальный сервер; cookie работают на локальном HTTP.

При отсутствии настройки или недоступности Neon сервер сообщает об ошибке; автоматического переключения в отдельную SQLite-базу нет. Для изолированной разработки укажите URL отдельной ветки Neon в `.env.local`.

Старая `.data/pingspace.sqlite` сохранена как резервная копия и больше не используется приложением. Команда `node scripts/migrate-to-postgres.mjs` переносит старые аккаунты с хешами паролей и брони в транзакции, без перезаписи конфликтующих аккаунтов и броней. Старые сессии не переносятся: после переключения нужно войти снова. Не запускайте перенос повторно при наличии уже перенесённых броней.

## Администратор

Один раз создайте учётную запись в терминале на сервере:

```cmd
npm run admin
```

Команда спросит e-mail, новый пароль и повтор пароля; ввод пароля скрыт. Учётная запись сохранится в той же базе. Если такой e-mail уже есть, команда назначит административную роль, установит новый пароль и завершит прежние сессии этого аккаунта.

На сайте нажмите «Вход администратора» внизу страницы и введите эти данные. Общего встроенного пароля и публичного демо-входа больше нет. Доступны все брони локации, фильтры и отмена. Пока действует тот же часовой предел отмены; отдельное исключение не согласовано.

## Бронирование

Выберите 1–3 стола, общую дату, длительность и начало. Время показывается только при доступности всех выбранных столов. После подтверждения создаётся одна групповая бронь; она отменяется целиком и остаётся в истории. Проверка доступности, цена, права пользователя и правило отмены выполняются на сервере; конкурирующие брони сохраняются в транзакции Postgres.

- Время: `Europe/Moscow`, круглосуточно, в том числе через полночь.
- Длительность: 30–240 минут, шаг 30 минут; начала также с шагом 30 минут.
- За каждый стол: первый час 800 ₽, далее 500 ₽/час; неполный час пропорционально.
- 30 мин — 400 ₽; 60 — 800 ₽; 90 — 1 050 ₽; 120 — 1 300 ₽; 150 — 1 550 ₽; 180 — 1 800 ₽; 210 — 2 050 ₽; 240 — 2 300 ₽. Сумма умножается на количество столов.
- Отмена — не позднее чем за 60 минут до начала, включая точную границу. Это проверяет сервер.
- Оплата в клубе. Прототип не связан с реальным клубным расписанием или платёжным провайдером.
- Горизонт 14 дней пока является демонстрационным значением `HORIZON_DAYS`.

## Проверки

```cmd
npm test
npm run build
```

Автоматические тесты покрывают тариф и время, групповую доступность, отмену, регистрацию и пароль, независимые сессии, повторный вход после перезапуска сервера, скрытие чужих данных, роли, конкурирующие брони и отклонение посторонних запросов. Браузерная проверка в независимых контекстах подтверждает регистрацию, вход с другого браузера, общую бронь, независимый выход, отмену и мобильную форму входа.

## Деплой Vercel

Production: https://pingspace-tau.vercel.app/ . В Vercel аккаунты, сессии и брони сохраняются в Neon Postgres, а не в локальном SQLite. DATABASE_URL подключается интеграцией Neon и не должен попадать в Git или архивы. Локальные серверы используют ту же Neon-базу при том же DATABASE_URL.

Конфигурация: vercel.json, api/index.mjs и server/postgres-store.mjs; runtime Vercel — Node 24.x. Транзакции создания и отмены групповой брони сериализованы advisory-lock в Postgres. Локальная база на момент первого деплоя содержала 0 аккаунтов и 0 броней; перенос пользовательских данных не требовался.

Для создания администратора именно в облачной базе: `vercel env pull .env.vercel.local --environment=production`, затем `node --env-file=.env.vercel.local server/admin.mjs`. Команда интерактивно запросит e-mail и пароль. Обычная `npm run admin` теперь автоматически читает локальный файл подключения и тоже изменяет Neon.

Проверено на production: API health/state, регистрация, вход из независимого браузера, общая бронь двух столов за 2 100 ₽ и её отмена. Контрольная запись отменена и не занимает столы. Локальные 25 тестов и сборка прошли.

Проверка реального Neon: `npm run test:postgres`. Она создаёт временный тестовый аккаунт и бронь, проверяет доступ из двух подключений, затем удаляет свои тестовые данные.
